# KA building conventions

_Every `KA-*` builder (human or agent) reads this page before touching files.
The tracker is `todo.md` - its **Standing guardrails** section is normative;
this page expands it into checklists and names the enforcing tests._

## 1. Exclusive files

- Your task's **Owns** list is the complete set of files you may create or
  edit. Work is new-file by design; if you find yourself "fixing" a file
  another task owns, stop.
- Files shared by the fleet - `agentic_ai/agents/cyber/kali.py`,
  `agentic_ai/agents/cyber/kali_v2.py`,
  `skills/agentic-roles/references/role-ops.md`, `AGENT_MATRIX.md`,
  `Makefile`, the CI file, deploy healthcheck scripts - are edited ONLY
  inside `[INTEGRATION]` tasks.
- Fixtures follow the shared layout: `tests/fixtures/README.md` is the dir
  contract; never invent fixture paths. Adding a dir there = a `todo.md`
  task, not a drive-by.

## 2. Module shape

Planner/mixin modules land at `agentic_ai/agents/cyber/<topic>.py`:

- One `class <Topic>Mixin:` per module; a mixin's docstring states its
  planning-only purpose. (Registered AGENTS differ: their CLASS docstring
  is the public /team/ card purpose - keep it complete, under 260 chars.)
- Large literal data lives as class-level or module-level constants;
  generated catalogs live in `data/*.json` produced by their committed
  `tools/build_*` script (never hand-edited).
- Shared input scrubbing is ONE module-level helper per concern plus a
  thin staticmethod wrapper on the class (house pattern: `wp_scrub_target`
  + `WebPentestMixin._wp_scrub_target`).
- Mixins never import the agent chassis; the chassis composes them
  (`KaliAgent(WebPentestMixin, RedTeamMixin, XssMixin, BaseAgent)` - that
  class line is integration-owned).
- Pure modules (bridges, sweepers, bundlers, replays) are plain modules;
  a clock, store, or transport may be injected exactly where the task's
  spec says so - otherwise none.

## 3. Op shape

- Ops return dicts. They never execute: **no `subprocess`, `os.system`,
  `eval`, or network calls in mixin/catalog/planner modules** - enforced
  by source-scan pins (house pattern: `assert "subprocess" not in code`,
  see `tests/test_redteam_ops.py::test_no_execution_and_no_payload_blobs`).
- Every op gets a docstring; its FIRST line becomes the CLI card's
  capability detail. Optional params get safe defaults; unknown kwargs from
  legacy callers are absorbed where the task documents acceptance.
- Guard the host boundary: consult the host agent's `validate_target` via
  `getattr(...)` with a silent fallback when absent, and scrub every
  external string through the module's scrub helper before use.
- URL lookups cap result size (house cap 25) and carry names + links +
  purposes only - never payload strings.

## 4. Catalog-data policy

- Catalogs are generated by a committed `tools/build_<topic>.py` script:
  every URL fetch-verified live (dead links dropped), deterministic JSON
  output, source/inspiration licensing recorded in the module docstring.
- External material is re-authored with credit - nothing verbatim, no
  payload listings regardless of license.
- The consuming module's test pins catalog structure and tool counts, and
  scans for leaked forbidden strings (payload/hostile patterns).

## 5. Test shape

- Test files: `tests/test_<topic>_ops.py` (mixin ops), `tests/test_<module>.py`
  (pure modules). Reusable corpus data goes to `tests/fixtures/` per the
  README contract - never inline blobs other tasks will want.
- No network in unit tests; offline mirrors/snapshots over live fetches;
  opt-in live variants live in `scripts/` and are owner-gated.
- Parametrize hostile inputs (house pattern:
  `tests/test_redteam_ops.py::test_scope_scrub_rejects`); pin op result
  SHAPES, not prose; pin catalogs (counts + schema).
- Expected tool sets and registry counts are pinned as named constants and
  updated in the SAME task that changes the set - the constant is the
  drift alarm, not a decoration.
- Lab/live batteries skip cleanly by default behind env-var gates (house
  precedent: `BRUTEFORCE_E2E=1`); anything live or destructive requires
  owner consent and follows kali_agent_v4's evidence discipline.

## 6. Suite baseline discipline

- `tests/test_ka_conventions.py::BASELINE_SUITE_TOTAL` pins the
  `pytest --collect-only` total over `tests/` (env-independent: conditional
  skips do not affect collection). Any task that adds or removes tests
  updates that constant in ITS OWN task. A loud mismatch on landing beats
  silent drift forever.
- Green = the verdict line reads `N passed, 0 failed`. Current
  env-conditional skips (not regressions): `BRUTEFORCE_E2E!=1` (3),
  `WAZUH_API_PASSWORD` unset (2), message-bus without reachable Redis AND
  without fakeredis (3), owner-gated KA_LAB_BATTERY lab battery (2,
  tests/lab/test_planner_parity.py). A NEW skip reason must be root-caused
  before merging.
- Read the verdict through a grep filter
  (`grep -E "[0-9]+ (passed|failed|error)"`), never from `tail`: the
  opentelemetry console exporter prints a cosmetic ValueError AFTER the
  summary at interpreter shutdown.
- The full suite runs in about 7 seconds. Run it before every commit.

## 7. Commit + push procedure

- Commits are authored AND committed as
  **Dawn Robbins <dmrobbipens@gmail.com>**; messages carry a lowercase
  prefix plus a short summary (e.g. `ka-p1: cve matching eval corpus`).
- Push BOTH remotes per task: `origin` (internal gitea over SSH,
  idm.wezzel.com) and `dmrobbi` (public GitHub over HTTPS), in lockstep.
  Never push the `github` remote (wezzels account; invalid token).
- GitHub HTTPS pushes authenticate through the gh CLI without exposing a
  token in a command, argument, or log:
  `git -c credential.helper= -c credential.helper='!gh auth git-credential' push dmrobbi main`
- Verify lockstep after pushing: `git ls-remote` on both remotes must show
  hashes equal to each other and to local HEAD.
- `todo.md` boxes for landed tasks are checked by the fulfilling task, in
  the same commit as the task's files.

## 8. Editing hygiene (out-of-sandbox sessions)

- Sessions whose workspace sandbox is not the repo root: the write/edit
  tools refuse `/home/wez/agentic-ai` ("Path escapes sandbox root"). Route
  edits through a Python writer/patch script written INTO the sandbox and
  run it with exec.
- Per-file all-or-nothing: every old anchor must occur EXACTLY once or the
  script aborts that file and prints the failing index; anchors come from
  fresh `grep`/`sed` reads of the current file, never from memory of the
  code's shape. Print per-file OK with the replacement count.
- Mind the EOF: files without a trailing newline make newline-assuming
  anchors score count=0 - inspect `repr(text[-140:])` first, then
  re-anchor.
- Shell: chain `cd` and git commands with `&&`. A failed `cd` followed by
  `;`-chained commands has committed work in the WRONG repo before; repair
  = `git reset --mixed HEAD~1` BEFORE anything is pushed.

## 9. Per-task acceptance checklist

- [ ] Files touched == the task's Owns list (nothing more, nothing shared).
- [ ] New tests green alone; FULL suite green after the change.
- [ ] `BASELINE_SUITE_TOTAL` updated in the task that moved the count.
- [ ] No network in unit tests; fixtures committed under `tests/fixtures/`
      per the layout README.
- [ ] Planner purity intact (no exec/network added by your module).
- [ ] Scrubs/guards used on every external input your ops accept.
- [ ] Commit as Dawn; both remotes pushed in lockstep; hashes verified.
- [ ] `todo.md` box checked in the same commit; shared wiring left for the
      phase's `[INTEGRATION]` task.
